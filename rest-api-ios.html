01

REST — що це таке

Принцип

REST — архітектурний стиль для спілкування клієнта (iOS-додаток) з сервером через HTTP. Запит = метод + URL + (опційно) тіло.

GET — отримати POST — створити PUT/PATCH — оновити DELETE — видалити
GET /users/42 → повертає профіль користувача з id=42
HTTP статус-коди
2xx — успіх 3xx — редирект 4xx — помилка клієнта 5xx — помилка сервера
200 OK, 201 Created, 401 Unauthorized, 404 Not Found, 500 Internal Server Error
02

URLSession — основний інструмент

Що таке URLSession

Це клас в Foundation, який керує мережевими запитами. Як менеджер пошти: ти даєш йому конверт (URLRequest), він відправляє і повертає відповідь.

let url = URL(string: "https://api.example.com/posts")!
let (data, response) = try await URLSession.shared.data(from: url)
Типи конфігурацій
.default — звичайний, з кешем .ephemeral — без кешу / cookies .background — завантаження у фоні
Для завантаження файлів коли додаток згорнутий → .background
URLRequest vs URL

URL — просто адреса.
URLRequest — конверт з адресою + метод, хедери, тіло.

var request = URLRequest(url: url)
request.httpMethod = "POST"
request.setValue(
  "application/json",
  forHTTPHeaderField: "Content-Type"
)
03

async / await — сучасний підхід

Чому async/await краще за completion handlers ❓ часто питають

Completion handler — це "зателефонуй мені коли буде готово". Якщо таких дзвінків багато — callback hell. async/await дає лінійний код без вкладених закриттів.

// Старий підхід — callback hell
fetchUser(id: 1) { user in
    fetchPosts(for: user) { posts in
        fetchComments(for: posts[0]) { comments in
            // ...
        }
    }
}

// Новий підхід — читається зверху вниз
let user     = try await fetchUser(id: 1)
let posts    = try await fetchPosts(for: user)
let comments = try await fetchComments(for: posts[0])
Повний GET-запит з async/await
func fetchPosts() async throws -> [Post] {
    let url = URL(string: "https://jsonplaceholder.typicode.com/posts")!
    let (data, response) = try await URLSession.shared.data(from: url)

    guard let http = response as? HTTPURLResponse,
          http.statusCode == 200 else {
        throw NetworkError.badResponse
    }

    return try JSONDecoder().decode([Post].self, from: data)
}
fetchPosts — як офіціант: пішов на кухню (сервер), зачекав, приніс страву (дані). async = він не блокує інших клієнтів поки чекає.
Task та @MainActor ❓ часто питають

async-функцію не можна викликати напряму з синхронного коду. Треба обернути в Task. UI оновлювати — тільки на MainActor.

// У ViewModel / View
Task {
    do {
        posts = try await fetchPosts()    // фоновий потік
        await MainActor.run {
            self.updateUI()               // повертаємось на main
        }
    } catch {
        print(error)
    }
}
04

Codable — парсинг JSON

Codable = Encodable + Decodable

Автоматично перетворює JSON ↔ Swift-структуру. Якщо ключі JSON збігаються з назвами полів — нічого додаткового не треба.

struct Post: Codable {
    let id:    Int
    let title: String
    let body:  String
}

// Decode
let post = try JSONDecoder().decode(Post.self, from: data)

// Encode
let data = try JSONEncoder().encode(post)
CodingKeys — коли ключі різні ❓ часто питають

JSON приходить у snake_case, а Swift-код у camelCase. Рішень два:

// Варіант 1: автоматично
let decoder = JSONDecoder()
decoder.keyDecodingStrategy = .convertFromSnakeCase

// Варіант 2: явно через CodingKeys
struct User: Codable {
    let firstName: String

    enum CodingKeys: String, CodingKey {
        case firstName = "first_name"
    }
}
API повертає "first_name", але в Swift хочемо firstName → CodingKeys як перекладач
05

Обробка помилок

Власний NetworkError enum ❓ часто питають
enum NetworkError: Error {
    case badURL
    case badResponse(Int)   // статус-код
    case decodingFailed
    case noInternet
}

// Використання
guard http.statusCode == 200 else {
    throw NetworkError.badResponse(http.statusCode)
}
Замість загадкового "щось пішло не так" — конкретний тип помилки, який можна обробити в UI
Що перевіряти після запиту
1. Чи взагалі отримали відповідь (URLError) 2. Чи це HTTPURLResponse (а не URLResponse) 3. Чи статус-код 2xx 4. Чи успішно декодуються дані
Не забудь кастити response as? HTTPURLResponse — інакше не доберешся до statusCode
06

Архітектура — як організувати код

NetworkManager / APIService ❓ обов'язково питають

Не пиши URLSession прямо у View чи ViewModel. Виноси в окремий шар — NetworkManager або APIService. View → ViewModel → Service → URLSession.

protocol PostsServiceProtocol {
    func fetchPosts() async throws -> [Post]
}

final class PostsService: PostsServiceProtocol {
    func fetchPosts() async throws -> [Post] {
        // URLSession логіка тут
    }
}

// ViewModel отримує через DI
final class PostsViewModel: ObservableObject {
    private let service: PostsServiceProtocol

    init(service: PostsServiceProtocol = PostsService()) {
        self.service = service
    }
}
Protocol + DI дозволяє підставити MockService в тестах — саме це питають про testability
POST-запит з тілом
func createPost(_ post: Post) async throws {
    var request = URLRequest(url: url)
    request.httpMethod = "POST"
    request.setValue("application/json", forHTTPHeaderField: "Content-Type")
    request.httpBody = try JSONEncoder().encode(post)

    let (_, response) = try await URLSession.shared.data(for: request)
    // перевіряємо статус...
}
07

Типові питання на співбесіді

Чим відрізняється URLSession від Alamofire?

URLSession — нативний, вбудований. Alamofire — бібліотека-обгортка над ним. Для більшості задач URLSession достатньо, Alamofire зручніший для складних сценаріїв (retry, interceptors). На співбесіді краще вміти обидва і пояснити коли використовуєш що.

Як уникнути retain cycle в мережевих запитах?

У Task і completion handlers використовуй [weak self].

Task { [weak self] in
    guard let self else { return }
    let data = try await self.service.fetchPosts()
}
Як скасувати запит?
var task: Task<Void, Never>?

task = Task {
    posts = try await service.fetchPosts()
}

// При deinit або зміні екрану
task?.cancel()
Як зупинити офіціанта — якщо вже передумав замовляти, cancel() скасує запит
Що таке URLCache?

Вбудований кеш відповідей. URLSession.shared автоматично кешує GET-запити. Можна контролювати через URLRequest.cachePolicy: .reloadIgnoringCache, .returnCacheDataElseLoad тощо.

Як браузер: не завантажує картинку заново якщо вже є в кеші
Як передати Authorization token?
request.setValue(
    "Bearer \(token)",
    forHTTPHeaderField: "Authorization"
)
