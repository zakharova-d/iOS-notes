01

ARC — Automatic Reference Counting

Що таке ARC

ARC — механізм управління пам'яттю в Swift. Він автоматично відстежує скільки місць у коді "тримають" об'єкт. Коли лічильник падає до 0 — об'єкт видаляється з пам'яті.

Як бібліотечна книга: поки хоч одна людина її тримає — вона існує. Всі повернули → книга зникає з полиці.
Reference Count у дії
class Dog {
    let name: String
    init(name: String) { self.name = name }
    deinit { print("\(name) видалено з пам'яті") }
}

var dog1: Dog? = Dog(name: "Рекс")  // count = 1
var dog2 = dog1                       // count = 2
dog1 = nil                            // count = 1
dog2 = nil                            // count = 0 → "Рекс видалено з пам'яті"
Важливо: ARC тільки для class ❓ часто питають

ARC працює лише з reference types — тобто class. Структури (struct) і перерахування (enum) — value types, вони копіюються і не потребують ARC.

class → ARC, heap struct → копія, stack enum → копія, stack
02

strong / weak / unowned

strong — за замовчуванням

Кожне звичайне посилання — strong. Збільшує лічильник на 1. Об'єкт живе поки є хоча б одне strong-посилання.

var cat: Cat? = Cat()  // strong, count = 1
weak

Не збільшує лічильник. Завжди Optional — може стати nil якщо об'єкт видалено. Безпечний варіант.

weak var delegate: MyDelegate?
Делегат, посилання на батьківський VC
unowned

Не збільшує лічильник. Non-optional — якщо об'єкт видалено і ти звертаєшся — краш. Використовуй тільки коли впевнений що об'єкт живе довше.

unowned let owner: Owner
Кредитна карта і власник — карта не існує без власника
weak vs unowned — коли що? ❓ часто питають
weak — якщо об'єкт може стати nil раніше (делегат, посилання між VC) unowned — якщо об'єкт точно живе стільки ж або довше (як self в замиканні всередині об'єкта)
На практиці — майже завжди weak. unowned — тільки якщо дійсно впевнений.
03

Retain Cycle — витік пам'яті

Що таке retain cycle ❓ обов'язково питають

Два об'єкти тримають strong-посилання один на одного. Лічильник ніколи не падає до 0 → обидва назавжди залишаються в пам'яті → memory leak.

class Person {
    var pet: Pet?          // strong
    deinit { print("Person видалено") }
}

class Pet {
    var owner: Person?     // strong → retain cycle!
    deinit { print("Pet видалено") }
}

var person: Person? = Person()
var pet: Pet?    = Pet()
person?.pet   = pet
pet?.owner    = person

person = nil   // deinit НЕ викликається — цикл тримає обох
pet    = nil   // deinit НЕ викликається
Як два чоловіки тримають один одного за руки в колі — жоден не може впасти, але й піти теж не може
Рішення — зробити одне посилання weak
class Pet {
    weak var owner: Person?  // weak → цикл розірвано ✓
}
Тепер Pet не "тримає" Person — якщо Person видалено, owner стане nil автоматично
04

Retain Cycle у замиканнях

Класичний retain cycle із closure ❓ обов'язково питають

Замикання — reference type. Якщо клас тримає замикання, а замикання захоплює self — цикл.

class ViewModel {
    var onUpdate: (() -> Void)?

    func setup() {
        onUpdate = {
            print(self.title)  // self захоплено strong → retain cycle!
        }
    }
}
Рішення — capture list [weak self]
func setup() {
    onUpdate = { [weak self] in
        guard let self else { return }
        print(self.title)  // ✓ цикл розірвано
    }
}
[weak self] — як тримати мотузку а не ланцюг: якщо треба — можна відпустити
Коли [weak self] НЕ потрібен

Якщо замикання не зберігається (non-escaping) — retain cycle неможливий. Наприклад, map, filter, forEach — вони виконуються одразу і не зберігаються.

// Тут [weak self] не потрібен
let doubled = numbers.map { $0 * 2 }

// А тут — потрібен (escaping closure, зберігається)
URLSession.shared.dataTask(with: url) { [weak self] data, _, _ in
    self?.handleData(data)
}
05

deinit — індикатор витоку

Що таке deinit і навіщо він потрібен

deinit викликається коли об'єкт видаляється з пам'яті. Якщо deinit ViewController-а не викликається після його закриття — є retain cycle і memory leak.

class ProfileViewController: UIViewController {
    deinit {
        print("ProfileVC видалено ✓")
        // якщо це не друкується після pop — шукай retain cycle
    }
}
deinit — як індикатор на приладовій панелі: якщо не спрацював коли мав — щось пішло не так
Як діагностувати витоки
1. Додай print у deinit — перевір чи викликається 2. Xcode → Debug → Memory Graph Debugger 3. Instruments → Leaks
06

Типові питання на співбесіді

Чим відрізняється stack від heap?

Stack — швидка пам'ять, struct/enum живуть тут, видаляються автоматично при виході зі scope.
Heap — динамічна пам'ять, class живуть тут, управляється через ARC.

Що станеться якщо використати unowned і об'єкт вже видалено?

Краш — EXC_BAD_ACCESS. Саме тому unowned лише коли на 100% впевнений що об'єкт живе довше. В сумнівах — завжди weak.

Чи може struct мати retain cycle?

Ні — struct є value type і копіюється. Але якщо struct містить властивість типу class — та class-властивість може бути учасником retain cycle.

Delegate pattern — чому delegate завжди weak?

Щоб уникнути retain cycle. Зазвичай VC тримає child view strong, а child view має делегат на VC. Якщо делегат strong — цикл. Тому:

protocol MyDelegate: AnyObject {}  // AnyObject → тільки class

weak var delegate: MyDelegate?       // weak → без циклу ✓
Протокол делегата має бути : AnyObject — інакше weak не можна використати
Як виявити memory leak на практиці?
print у deinit — найшвидший спосіб Memory Graph Debugger в Xcode (Debug → Memory Graph) Instruments → Leaks — для детального аналізу
