01

Базові концепції

Commit, Branch, HEAD

Commit — знімок стану коду в момент часу.
Branch — незалежна лінія розробки.
HEAD — вказівник на поточний commit (де ти зараз).

Commit — як збереження в грі. Branch — як паралельне проходження. HEAD — твоя поточна позиція.
Щоденний workflow
# Створити гілку і переключитись
git checkout -b feature/login-screen

# Подивитись статус
git status

# Додати файли
git add .                        # всі файли
git add LoginViewController.swift  # конкретний файл

# Закомітити
git commit -m "feat: add login screen UI"

# Запушити
git push origin feature/login-screen
02

merge vs rebase

git merge — зберігає історію ❓ обов'язково питають

Створює новий "merge commit" який об'єднує дві гілки. Історія зберігається повністю — видно що гілки існували окремо.

# Знаходимось на main, мерджимо feature
git merge feature/login-screen
Як злиття двох річок — видно де кожна починалась, є точка злиття
git rebase — чиста лінійна історія ❓ обов'язково питають

Переносить commits з однієї гілки "поверх" іншої. Переписує SHA commits. Історія виглядає як ніби гілки не було.

# Знаходимось на feature, ребейсимо на main
git rebase main

# Після rebase — force push (бо SHA змінились)
git push --force-with-lease
Як переклеїти стікери з одного стовпця на інший — вони ті самі, але виглядають як одна лінія
Ніколи не робити rebase на shared branches (main, develop) — переписуєш історію для всіх
Коли що використовувати
merge — для об'єднання feature в main/develop rebase — щоб підтягнути зміни з main у свою feature-гілку interactive rebase — щоб прибрати/об'єднати commits перед PR
Interactive rebase — squash commits
# Об'єднати останні 3 commits в один
git rebase -i HEAD~3

# У редакторі:
# pick abc123 feat: add login UI
# squash def456 fix: typo
# squash ghi789 fix: button color
Squash — прибрати "fix typo", "wip", "oops" перед тим як відкрити PR
03

git cherry-pick

Що таке cherry-pick ❓ питають

Переносить конкретний commit з однієї гілки на іншу. Корисно коли потрібно взяти тільки один фікс без всієї гілки.

# Знаходимось на main
# Хочемо взяти тільки один commit з hotfix-гілки
git cherry-pick abc1234

# Кілька commits
git cherry-pick abc1234 def5678
Як взяти один рецепт з кулінарної книги не купуючи всю книгу — критичний hotfix в main без решти feature
04

git stash

Stash — тимчасово сховати зміни

Зберігає незакомічені зміни "в ящик" щоб переключитись на іншу гілку і повернути потім.

# Сховати зміни
git stash

# Подивитись що є в stash
git stash list

# Повернути останні зміни
git stash pop

# Повернути конкретний stash
git stash apply stash@{1}

# Стеш з назвою
git stash push -m "WIP: login animation"
Стеш — як покласти роботу в шухляду: переключився на термінове завдання, потім дістав і продовжив
05

reset vs revert

git reset ❓ питають

Переміщує HEAD назад, видаляє commits з історії.

# Скасувати commit, зберегти зміни
git reset --soft HEAD~1

# Скасувати commit і зміни
git reset --hard HEAD~1
Не використовувати на pushed commits — переписує публічну історію
git revert

Створює новий commit який скасовує зміни. Безпечно для shared branches.

# Безпечно скасувати commit
git revert abc1234
Для main/develop — тільки revert, ніколи reset
06

Git Flow для iOS команди

Типовий процес у команді
1. main — стабільний код, тільки через PR 2. develop — інтеграційна гілка 3. feature/xxx — нова функціональність 4. hotfix/xxx — термінові фікси прямо в main 
# Типовий цикл фічі
git checkout develop
git pull
git checkout -b feature/profile-screen
# ... робота ...
git rebase develop        # підтягнути свіжі зміни
git push origin feature/profile-screen
# відкрити Pull Request → code review → merge
07

Типові питання на співбесіді

Що таке конфлікт і як вирішити?

Конфлікт — два розробники змінили той самий рядок по-різному. Git не знає яку версію залишити і позначає конфлікт у файлі.

<<<<<<< HEAD
let color = UIColor.blue    // твоя версія
=======
let color = UIColor.red     // версія з main
>>>>>>> main

# Обираємо потрібну версію, видаляємо маркери, комітимо
git add .
git commit
git fetch vs git pull?

fetch — завантажує зміни але не застосовує. pull = fetch + merge. Краще робити fetch + rebase для чистої історії.

git fetch origin
git rebase origin/main   # замість git pull
Що таке .gitignore в iOS проєкті?

Файли які не треба комітити: .DS_Store, папка Pods/ (якщо є Podfile.lock), *.xcuserdata, DerivedData/, секретні ключі та API tokens.
